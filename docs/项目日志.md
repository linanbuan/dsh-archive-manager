## 2026-10-24 · 2.0.0：归档会话管理重写

版本：`2.0.0`；实测宿主：DSH `0.2.1-rc.3` 桌面版。
范围：`index.js`、`lib/*.js`、`client.js`、`README.md`、`README.en.md`、`docs/项目日志.md`。

### 1. 现状问题

1. **首屏必须折叠全部日志。** 1.x 为了显示标题，对每一条归档会话调用标题折叠（`sessionQuery.readTitleSnapshots`）。
   一台有 162 条归档会话的机器上，这就是首屏先打开并重放 162 个会话日志，刷新一次要等数秒。
   工作量的绝对值并没有那么夸张，问题是它发生在**首屏绘制之前**。
2. **只能一行一行处理。** 删除走行内二次确认，没有多选、没有批量、没有撤销以外的补偿手段；
   归档会话攒到上百条时，清理一次要点上百次，且误点的代价和批量一样高。
3. **找一条会话只能滚。** 没有搜索，也没有按状态过滤（运行中 / 已无日志）。
4. **布局不属于设置页。** 页面自带高度与滚动条，和设置面板的滚动容器争滚动；
   在窄列里行内容容易挤成一团。
5. **删除的判定散落在路由里。** 判定是对的，但没有一处「把所有前置条件写在一起、可被测试整体打靶」的地方。

### 2. 调研

- **成熟清理页的交互模型（zcode 等）**：多选 + 批量操作 + 即时本地筛选是标配；破坏性操作弹**一次**确认框，
  并把每个目标的处理结果（成功 / 失败原因）逐项回显；内容级搜索默认关闭，开启后显示进度条且可中断。
  结论：本插件照这个模型重写，但**不**把内容搜索设成默认行为 —— 它是唯一会打开日志的路径。
- **DSH 0.2.1-rc.3 的插件规范**：组合包 = `dsh.bundle.patch` + `dsh.client`；浏览器半部注册
  `settings.section` 槽位与 `locale` 字典；Host 半部用 `ctx.connection.fetch.register` 注册路由，
  由该通道负责会话鉴权与 Host/Origin 校验。
- **本轮实际依赖的宿主接口**（都是内部实现，不是稳定 API）：
  `sessionQuery.listSessions / readTitleSnapshots / filterEvents`、
  `sessionProjectionCache.cachedSnapshot / cachedPredecessorTitle`、
  `workspaceRegistry.archivedSessionIds / pinnedSessionIds / list() / unarchiveSession`、
  `sessions.list()`、`sessionPersistence.list()`（退路）、`ctx.emit('api-session/removed', id)`。
- **决定性结论**：`dsh-session-persistence-jsonl` 的文档写明「没有任何东西会删除会话文件……这个接缝没有删除 API」，
  `workspaceRegistry` 只负责记账。所以「永久删除」不可能是调用一个现成 API，而是插件在**自己推导的路径**上做文件系统操作
  —— 这直接决定了 3、5 两节里的大部分设计：路径推导必须可判定，判定必须集中，顺序必须可恢复。

### 3. 改动清单（按文件）

**`index.js`（Host 半边）**
- 五条路由：`GET /api/archive/sessions|titles|search`、`POST /api/archive/restore|delete`。
- 所有回答都是 HTTP 200 + `ok` 判别式：业务拒绝不能被误认成通道鉴权失败。
- `readBody` 统一校验 JSON 对象；`guard` 把异常转成 `{ok:false, code, message}`，不抛出到通道。
- 删除路由要求 `confirm: true`（`dryRun: true` 例外）：页面上的确认框是礼貌，协议里的字段才是闸门。
- 标题/搜索的边界写在路由里：单次标题最多 200 个 id、预算上限 30s；内容搜索每页默认 8（最多 24）、
  预算默认 2500ms（最多 8000ms）。

**`lib/snapshot.js`（快照）**
- **两级读取**：快照层 = 一次 header 列表（`listSessions`，把运行中的会话合并到持久化之上）+ 一次会话根目录的两级扫描
  （编码 id → 目录，比按推导路径逐条 `stat` 便宜，还能发现目录放错位置的会话）+ 每行一次 `readdir` / 每个日志一次 `stat`；
  标题只读宿主已加载的投影缓存（零 I/O）。**这一层不打开任何会话日志。**
- 标题补齐层：`readTitles(ids, {budgetMs, batch})` 折投影缓存答不出的行，返回 `{titles, pending, failed}`，
  单条折叠被拒只进 `failed`，不牵连整批。
- `DEFAULTS` 把八个可调项与默认值集中在一处（`headersTtlMs` 15000、`snapshotTtlMs` 4000、`diskTtlMs` 3000、
  `titleTtlMs` 600000、`titleBatchSize` 24、`titleBudgetMs` 6000、`concurrency` 12、`maxBatchSize` 500）。
- 缓存代际：`invalidate()` 让 generation 加一并清掉 header 快照、目录扫描、目录事实与已建快照；
  批量操作成功后调用它，下一次读一定读到自己写入的结果。

**`lib/ops.js`（批量操作）**
- `normalizeIds`：只收字符串数组、去空去重、上限 `maxBatchSize`，越界报 `TOO_MANY_IDS`。
- `restore`：逐 id 移出归档集合，失败隔离并逐项报告（`NOT_ARCHIVED` / `RESTORE_FAILED`）。
- `remove`：**先重新观测一次快照**，再逐 id 过守卫（归档集合 → live → header → 在盘 → `assertDeletableDirectory`），
  然后 `rm(directory, {recursive:true, force:false, maxRetries:3})`，再 best-effort 删投影缓存文件，最后才 `unarchiveSession`。
  「文件已删、记录没摘掉」单独报 `UNARCHIVE_FAILED`，不假装整批失败。删除并发固定 4 路。

**`lib/search.js`（匹配规则）**
- 一套规则同时服务 Host 过滤与内容搜索的片段：`compileQuery`（trim、500 字符上限、按空白切词、小写）、
  `rowMatches` / `matchedFields`（多关键词 AND、逐词可落不同字段）、`snippetAround`（首词两侧各 60 字符、折叠空白、加省略号）。
- 规则放在这里而不是浏览器包里，是为了让「什么算命中」只有一个定义，测试也只打一个靶。

**`lib/concurrency.js`（并发）**
- `mapLimit`：保序、最多 N 个 worker、第一个失败即抛出；`settleLimit`：把每项失败装进 settled 信封。
- 之所以单独成文件：一次几百个目录时，等待是顺序的，工作量不是；受限重叠能把等待挪走，又不让句柄数失控。

**`lib/layout.js`（布局，1.x 已有，本轮未改结构）**
- `projectKey` / `encodeSegment` 继续按 DSH JSONL 后端的规则移植；`assertDeletableDirectory` 保持「不能证明就拒绝」。

**`client.js`（浏览器半边，整页重写）**
- 布局改为**设置面板内的流式区块**：不自带高度、不自带滚动条，列宽上限 720px，随设置面板滚动。
- 工具条（搜索、内容搜索开关、开始/停止、刷新）、状态筛选（全部 / 可删除 / 运行中 / 仅记录，带计数）、
  排序（最近更新 / 创建时间 / 体积 / 标题）、统计行、列表头（全选当前页）、60 行分页、吸底选中条。
- 多选：勾选框 + <kbd>Shift</kbd> 区间（锚点 + 可见列表）；全选只作用于当前页。
- 删除：确认对话框（前 8 条 + 「还有 N 个未列出」），确认后 POST `{ids, confirm:true}`；
  结果提示 9 秒自动消失，失败最多列 4 条「标题 — 原因」。
- 标题补齐循环：投影缓存答不出的行，每批 24、最多 24 轮，补到的标题直接 patch 到已渲染的行，不重排列表。
- 内容搜索：按 cursor 分页续扫，显示进度与命中片段，可随时停止；关掉开关即丢弃命中。
- 注册：`locale` 字典（`zh`/`en` 键集合一致）+ `settings.section`（`id: archived-sessions`，`order: 100`）。

**其它**
- `cordis.patch.yml` 行 id 保持 `archive-manager`（停用与改配置都按它定位），`package.json` 版本升到 `2.0.0`、
  简介改成 2.0.0 的能力描述；`locale/{zh,en}.json` 同步简介。
- 文档：`README.md` / `README.en.md` 按新实现重写；新增本文件。

### 4. 性能取舍

- **首屏不读日志**：这是本次重写的核心取舍。代价是首屏可能先显示一批「（无标题）」，随后被补齐；
  换来的是首屏延迟与归档条数基本解耦。
- **标题补齐而不是首屏折叠**：每批 24、单次 6s 预算、整轮最多 24 轮。补到的标题只补行，不重排序，
  避免用户在读列表时看到顺序跳动。
- **短 TTL 分三级**：header 列表与根扫描 15s、整快照 4s、单目录事实 3s（折叠出来的标题另有 10 分钟）。选这么短，是因为这一页的用户动作就是「删完再看结果」，
  缓存太长寿会让人怀疑操作没生效。
- **代际失效**：批量操作后 generation+1，保证「操作 → 立刻看到新列表」；代价是操作后第一次读稍贵，可以接受。
- **并发是内部常量还是配置项**：`concurrency`（12）暴露给用户；根目录扫描 8 路、每目录日志 `stat` 4 路、
  删除 4 路是内部固定值 —— 它们跟机器和磁盘关系不大，暴露出去只会增加解释成本。
- **内容搜索按需分页**：默认关闭；开一次请求只扫一页（默认 8 个会话、2500ms），由页面用 cursor 续扫。
  代价是一次全库搜索要多次往返；换来的是不阻塞首屏、可中断、单次请求不会拖垮通道。
- **放弃的方案**：（a）首屏全量折叠标题 —— 回到 1.x 的老问题；（b）把体积/时间也塞进整份快照缓存 ——
  一次删除后整表重算；（c）内容搜索一次性全库扫描 —— 大库必然超时且不可中断。

### 5. 安全边界复核

逐条复核后固化在 `lib/layout.js` 的 `assertDeletableDirectory` 与 `lib/ops.js` 的 `remove`：

1. **唯一输入是会话 id**。浏览器无法指定路径。载荷里确实带绝对路径字段（`directoryPath` / `homePath` /
   `sessionsRootPath`），但删除判定**不读**它们：Host 从 id 与 header 重新推导。
2. **必须在归档集合里**（`NOT_ARCHIVED`）—— 每次批量删除前重新读一次 `archivedSessionIds`。
3. **不能是运行中的会话**（`SESSION_LIVE`）—— 每次读 header 时都用 `sessions.list()` 覆盖 liveness，即使 header 列表命中缓存。
4. **根包含与两级定位**：路径严格在 `$DSH_HOME/sessions` 下且不等于根（`OUTSIDE_ROOT`），恰好「项目层/会话层」两级（`MISPLACED`）。
5. **编码名相等**：项目目录名 = `projectKey(cwd)`（`PROJECT_MISMATCH`）、会话目录名 = `encodeSegment(id)`（`ID_MISMATCH`）。
   编码是单射的，所以这是可判定的相等，不是模糊匹配。
6. **必须真的有会话日志**（`NOT_A_SESSION_DIRECTORY`），否则按「看不懂的目录」拒绝。
7. **先删文件、后摘记录**：中途失败时该会话仍然「已归档」且可见；只有「文件已删、记录未摘」会明说（`UNARCHIVE_FAILED`）。
8. **复原只动归档列表**：`unarchiveSession` 不碰日志与投影缓存；会话本来就在工作区占着记账槽位。
9. **广播一次**：成功项（含 `UNARCHIVE_FAILED`）才 `emit('api-session/removed')`，被拒绝的项不广播。
10. **协议闸门**：`confirm: true` 缺失整批 `CONFIRM_REQUIRED`，不会「部分删了再说」。

### 6. 验证方式

**自检**：`node test/selfcheck.mjs`（或 `pnpm test`）。本轮实际跑出来的结果：

```
50 checks, 0 failed          # 退出码 0（2026-10-24，本机 Windows / Node）
```

覆盖面（按 50 项归组）：

- 布局与判定（4）：`encodeSegment` 与真实转义一致、`projectKey` 复现真实目录名、`sessionDirectory` 拼接、
  `assertDeletableDirectory` 拒绝所有不能证明的情况。
- 路由与快照（9）：五条路由注册、异常转 `ok:false`、列表 totals、行字段齐备、异常形状不被丢、
  每行给出不可删原因、TTL 内复用 header 列表、`?refresh=1` 重读、批量操作后代际失效。
- 标题（5）：缓存命中与「缓存里的 null 也是答案」、titles 路由补齐、翻页与单条被拒、空 id 列表拒绝、`titleText` 兼容多种形状。
- 搜索（5）：多字段过滤、逐词 AND + 大小写、空查询与未挂载 `sessionQuery`、命中/片段/skipped、逐页推进直到 `done`。
- 批量操作（14）：复原单项/批量/失败隔离、删除成功、`dryRun`、缺 `confirm` 拒绝、运行中拒绝、缺目录与缺 header 区分、
  无日志目录拒绝、错项目层拒绝、坏 ids 拒绝、拒绝时磁盘原封不动、广播次数、`UNARCHIVE_FAILED` 如实报告。
- 纯函数（6）：`lib/search.js` 三组、`lib/concurrency.js` 三组。
- 客户端（7）：导出与注册（字典 + 一个 settings.section）、字节格式、筛选、排序（无标题垫底）、
  区间选择 / 标题 patch / 体积汇总、两份字典键一致。

**没有覆盖的部分**（如实记录）：
- 真实渲染：没有 React 运行时，不驱动 hook 与 DOM，点击流程是照着页面导出的 `__test` 纯函数断言的；
- 真实 Harness 服务：测试用的是假 harness（假归档集合 / header / 投影缓存 / `filterEvents`），
  `/api` 通道的鉴权与 Origin 校验不在覆盖范围；
- `sessionQuery` 未挂载时的 `sessionPersistence` 退路（只断言了搜索路由的 `UNAVAILABLE`）；
- 三个 TTL 的**过期**行为，只在「TTL 内复用」这一侧断言。

**安装验证**：本轮在 DSH `0.2.1-rc.3` 桌面端用插件页装了一遍 2.0.0：对话框显示包名、版本与简介，

### 7. 遗留问题与后续可做项

- **内容搜索的下一步是索引**：现在每次打开日志。DSH 生态里已有 `dsh-session-query-sqlite`，
  接它可以把这个按需扫描换成查询；风险是引入额外存储与索引一致性维护，得先确认它在目标部署里一定挂载。
- **按项目分组视图**：目前只有筛选与排序。分组要做折叠状态、可能的虚拟滚动，收益在归档量大且项目多时才明显。
- **导出清单**：把当前筛选结果导成 CSV/JSON（id、标题、项目、体积、时间），便于先在外部核对再删。
  这是「批量删除」最自然的搭档 —— 删之前想留档的人现在只能截图。
- **风险：没有声明 `engines.dsh`**。插件页因此不会替用户拦版本不匹配；升级 DSH 后行为异常时，先确认版本兼容。
- **风险：依赖内部接缝**。`sessionQuery` / `sessionProjectionCache` / `sessions` 都是内部实现，
  宿主改名或改形都会让这一页退化（错误提示或空列表），但不会影响 Harness 启动。
- **测试的边界**：假 harness 能证明判定逻辑，不能证明真实通道行为；真实安装与真实数据仍需要在桌面端手工过一遍。
